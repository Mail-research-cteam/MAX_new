# MAX_new — прототип бота и редактор сценариев

Статическое приложение для UX-исследований. Рабочая версия находится в `prototype/`. Сервер не принимает загрузки и не записывает файлы: изменения редактора хранятся в браузере и скачиваемых версиях.

**Лицензия кода пока не выбрана владельцем.** Публичная доступность репозитория сама по себе не предоставляет разрешение на повторное использование кода. Не публикуйте подготовленный комплект как свободно лицензированный проект до решения владельца. См. `THIRD-PARTY-NOTICES.md` для ресурсов других авторов.

## Запуск чистой копии

Нужен Node.js 20 или новее. Из папки проекта:

```text
node tools/preview.cjs
```

Откройте:

- `http://127.0.0.1:8000/prototype/index.html` — покупка;
- `http://127.0.0.1:8000/prototype/index.html?scenario=owner` — владелец;
- `http://127.0.0.1:8000/prototype/index.html?scenario=employee` — сотрудник;
- добавьте `&edit=1` к адресу сценария для редактора;
- `http://127.0.0.1:8000/prototype/mail.html` — стартовая страница.

Установка npm-пакетов для обычного запуска не нужна. Не открывайте HTML двойным щелчком: браузеру нужно загружать JSON через HTTP. Остановка сервера — Ctrl+C. Если порт занят: `node tools/preview.cjs --port=8001` и используйте этот порт в адресах. Для отдельной копии можно указать `--root=путь-к-копии`.

По умолчанию сервер доступен только этому компьютеру. `--lan` открывает доступ из локальной сети ко всем разрешённым файлам папки сервера; используйте его только с подготовленным комплектом без личных материалов.

## Данные и версии

Верхнее меню сценария содержит сохранение JSON, импорт, открытие сохранённой версии, предыдущую и файловую версии. JSON-файлы в `prototype/scenarios/` — исходники. Браузерные черновики и сохранённые версии относятся только к текущему адресу сайта и браузеру; они не отправляются на GitHub и не меняют файлы на диске. В меню указан текущий источник данных.

Изменённый файловый источник и старый черновик вызывают предупреждение. Резервные копии не очищаются автоматически. Перед очисткой браузера скачайте JSON или ZIP. При повреждённой сохранённой версии открывается файловая версия, исходные данные хранилища сохраняются. При недоступном хранилище можно скачать JSON.

Исследовательские тексты, связи, задержки и ручные координаты меняйте осознанно. «Навести порядок» меняет координаты по явному нажатию, поддерживает отмену. Добавление «Списка контактов» создаёт связанную карточку «Новый чат». Пустые цели исследовательских кнопок не заменяются произвольными переходами.

Изображения можно выбрать или перетащить в сообщения; они встроены в JSON и ZIP. Файлы должны быть собственными или разрешёнными к использованию. Фото, GIF и экспортируемые сценарии могут содержать личные сведения и метаданные: проверяйте их перед распространением. Лимит JSON-импорта — 20 МБ, до 1000 узлов, 200 действий на узел и 1000 контактов. Задержки должны быть неотрицательными.

## Свой HTML-экран

Обычные ссылки респондента используют файловую версию и не подхватывают старую сохранённую версию автора. Команда «Открыть сохранённую версию» явно добавляет `saved=1`; этот параметр открывает локальную сохранённую версию в текущем браузере. Так же можно проверять варианты в редакторе экспортированного комплекта, не меняя обычную ссылку для респондентов.

Сохраните HTML и ресурсы внутри `prototype/`; в карточке «Внешняя страница» укажите относительный путь, например `my-screen.html`. Экран откроется в отдельной вкладке. Для стартового экрана ссылка на `index.html?scenario=owner` запускает сценарий заново и не является возвратом в существующий чат.

Для включения дополнительного экрана в ZIP создайте `prototype/release-extra.json`:

```json
{"files":["my-screen.html","assets/my-screen.png"]}
```

Затем выполните `node tools/package-shared.cjs`. Не используйте дисковые пути, адреса localhost в опубликованных переходах и пути с начальным `/` для сайта репозитория. Имена файлов чувствительны к регистру на GitHub Pages. Внешние скрипты, подключения и небезопасные схемы URL ограничены политикой безопасности; локальные HTML/CSS/JS и ресурсы поддерживаются.

## Автосохранение в локальный файл

В Chrome или Edge включите тоггл **«Автосохранение»**, выберите файл и разрешите запись. В автономном режиме выбирается HTML, в основном редакторе — JSON текущего сценария (можно выбрать файл в `prototype/scenarios/`). После выбора текущая версия сохраняется сразу, затем раз в 2 минуты — только при изменениях. Состояние «Сохранено в ЧЧ:ММ» отображается под тогглом. Повторное нажатие отключает автосохранение.

Файл другого сценария не перезаписывается. Если выбранный файл содержит другую версию текущего сценария, редактор запросит подтверждение замены. При внешнем изменении файла, потере разрешения или ошибке записи автосохранение останавливается; изменения остаются в редакторе. Выберите файл заново после проверки версий или скачайте отдельную копию.

В автономном HTML черновик записывается в браузер через 300 мс после правок. При повторном открытии того же файла редактор предложит восстановить отличающийся черновик. Отказ не удаляет черновик; файлы с разными путями изолированы. Если браузер запретил хранилище или исчерпана квота, редактор показывает предупреждение. Это дополнительная страховка, а не замена записи на диск.

После открытия страницы заново файл нужно выбрать повторно. Вкладка должна оставаться открытой; в фоне браузер может задерживать интервал. В браузерах без записи в файл доступно обычное скачивание HTML/JSON. Запись JSON не добавляет новый сценарий в каталог автоматически и не отправляет изменения на GitHub.

## Автономный HTML для коллег

В редакторе нажмите **«Скачать HTML»**. Один файл содержит выбранный флоу, редактор, локальные ресурсы и экраны почты/пароля. Его можно отправить коллеге и открыть двойным щелчком без Node.js, сервера и интернета. Внешние интернет-ссылки по-прежнему требуют подключения. Другие флоу нужно экспортировать отдельно; ссылки на них не подменяются текущим сценарием.

Файл сразу открывается в редакторе. Внесите правки и нажмите **«Скачать HTML»**. Браузер скачает новую копию; исходный файл на диске не перезаписывается. В автономном режиме черновики других файлов не подхватываются; после правок скачайте файл до закрытия или включите автосохранение и дождитесь состояния «Сохранено». Переходы на локальные экраны открываются поверх текущего флоу, кнопка «Назад» браузера или Escape возвращает к нему.

Кнопка **«Скачать JSON»** скачивает актуальный сценарий для добавления или замены файла в `prototype/scenarios/`; отправка на GitHub выполняется отдельно.

Чтобы вернуть правки в проект, в меню сценария основного редактора выберите **«Импорт JSON / HTML»** и откройте полученный HTML. Импорт извлекает только данные сценария, не запускает код полученного файла. Затем выберите **«Сохранить версию + JSON»**, замените соответствующий файл в `prototype/scenarios/`, проверьте и отправьте изменения на GitHub. Импорт сам по себе не перезаписывает исходники.

Команды экспорта JSON и ZIP остаются в меню сценария. Экспортированный HTML фиксирует версию редактора на момент скачивания; обновления сайта не меняют уже переданные файлы. Не редактируйте одновременно несколько копий одного флоу без согласования: автоматического объединения изменений нет.

Браузерная проверка автономного режима: `node tools/check-html-browser.cjs` после установки зависимостей и Chromium. Она проверяет все три сценария, повторный экспорт, импорт данных, экраны почты/пароля и отсутствие сетевых запросов. Локальный сервер для этого теста не нужен.

## ZIP и GitHub Pages

Перед скачиванием ZIP обновите список: `node tools/package-shared.cjs`. ZIP фиксирует текущий выбранный сценарий; остальные сценарии берутся из файлов. Сохранённые только в браузере изменения других сценариев нужно экспортировать отдельно. Обычный режим распакованного комплекта использует зафиксированные файлы, а режим редактора поддерживает локальные варианты.

Для публичного исходного репозитория используйте `npm run prepare:public`: команда создаёт **новую отдельную папку** в `dist/`, ничего не удаляя. Она не копирует архивы, скриншоты, отчёты, приватные фикстуры и личные настройки. Это кандидат на публикацию, а не автоматическое разрешение публикации. Лицензия проекта остаётся открытым вопросом.

GitHub Pages может обслуживать статические файлы. В исходном репозитории используйте адрес `/имя-репозитория/prototype/mail.html` или `/prototype/index.html`. Для ZIP можно разместить его распакованное содержимое в корне сайта. Публикация редактора не создаёт серверного сохранения: другим людям видны только загруженные в репозиторий/Pages файлы.

## Проверки

```text
npm ci
npx playwright install chromium
npm test
```

В другом терминале запустите `node tools/preview.cjs` на порту 8000, затем `npm run test:browser`. Браузерные проверки используют отдельные временные профили, не пользовательский профиль и не ваши черновики. На Windows с установленным Edge можно вместо установки Chromium задать `$env:PW_BROWSER_CHANNEL='msedge'`. Альтернатива — `PW_EXECUTABLE_PATH` с явным путём к браузеру. Личных путей в коде тестов нет.

Обязательные проверки также запускаются отдельно: `node tools/check-board-unit.cjs`, `node tools/check-board-browser.cjs`, `node tools/check-board-stress.cjs`, `node tools/check-shared.cjs`. Артефакты генерируются в `audit-max/`, фикстуры — в `tools/fixtures/`; эти папки не публикуются.

Проверка всех достижимых маршрутов — `node tools/check-player-paths.cjs`: используется виртуальное время браузера с сохранением исходных задержек. Это не физическое ожидание и не проверка реального трекпада/телефона. Для изоляции от внедряемых антивирусом скриптов `AUDIT_SOURCE_HTML=1` подаёт исходный HTML напрямую в тест; результат такого запуска отмечается отдельно от обычного сетевого.

## Устройство проекта

- `shared/app.js` — проигрыватель, состояние чатов, история редактора, карточки;
- `shared/author.js` — версии, черновики, импорт и ZIP;
- `shared/safety.js` — проверка форматов, URL и путей;
- `shared/board.js` — геометрия, связи, выделение, перемещение и масштаб;
- `shared/editor-ui.js` — оформление существующих элементов редактора;
- `shared/respondent.js`, `boundary.js`, `message-media.js` — экраны респондента и изображения;
- `scenarios/` — каталог и три исследовательских сценария.

Все указанные пути `shared/` и `scenarios/` находятся внутри `prototype/`. Архивный `tools/build-shared.cjs` не используйте.
